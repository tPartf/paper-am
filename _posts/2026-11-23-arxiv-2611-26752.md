### 2. 影响力与开源
这不是替换 LoRA 的优化器，而是一个改变预填充表征的模块，能与 LoRA 和全参数微调配合。公开的是预印本和其中的方法、实验表及评审提示；未查到可核实的作者项目仓库或新权重链接，不宜标作已开源。

### 3. Introduction
反复运行 Transformer 主干可以逐次细化状态，但计算串行。一次性添加多个可学习 token 则高效，不过没有专门的逐级细化路径。论文问的是：能否只在这些额外 token 的表征上建立递推，不再反复执行主干？

### 4. Background
LoopLM 复用同一组 Transformer 层，省的是参数而非循环计算；普通可学习 token 可随主干在一次前向生成表征，但没有论文新增的显式残差链。这里的“深度”首先指 token 状态之间的递推，不是堆叠新的 Transformer 层，也不等同于增加显式文字推理步数。

### 5. GPU 训练与数据报告
§5 默认 Qwen3-VL-2B-Instruct、LoRA rank 64、AdamW、学习率 2×10⁻⁴、有效批大小 1,024、20,000 更新、32 张 H100；检索用 4 个额外 token，生成用 16 个。附录另有 2B 全参数、8B LoRA 及 30B-A3B LoRA 对照。表 9 计时另用 16 张 H100、FSDP2、bf16，不能和训练机器数混同；论文没有给出完整运行 GPU 小时。

### 6. 目标与方法直觉
首先让主干一次生成各 token 的上下文状态 eₖ，再用 zₖ = βₖzₖ₋₁ + αₖeₖ 把先前状态与当前状态混合。α 初始为 1、β 为 0，起点等价于无残差链对照。检索对同位 token 的余弦相似度求均值，用 InfoNCE 训练；生成用链上状态参与条件预测，回答仍然自回归生成。细化发生在浅层的线性更新中，不是让主干隐式多跑几次（§3）。

### 7. 贡献与创新
- §4 的一步下降优势是局部梯度结论：新增递推系数收到非零梯度、且步长足够小时才严格成立。它不保证 AdamW 的长期训练或测试集精度一定更好。
- GSM8K 上，2B 完整方法 / 无残差 / 全主干循环分别为 71.11% / 68.52% / 70.88%；MATH-500 为 82.40% / 81.60% / 79.80%（表 3–4）。MMEB‑V2 汇总为 65.9±0.2，在表 1 的“不额外用训练数据”组居首，但低于另一个使用额外数据的方法 66.5。
- 表 9 的 K=16 设定下，相对全主干循环，每步训练由 22.04 s 到 1.85 s、推理由 7.24 s 到 1.70 s，约为 11.9× 和 4.3×；无残差的单次前向对照为 1.78 s 和 1.67 s，说明收益是相对循环基线的取舍，而非把所有单次前向都加速。

### 8. 数据、工具与平台
检索选用 MMEB‑V2，以及 CIRR、MSCOCO、MSVD、QVHighlights；问答选用 GSM8K、MATH-500、Natural Questions、HotpotQA。附录提供按层施加模块的探索和 LLM 裁判提示词。计时结果依赖论文的序列长度、批大小和多卡配置，不能直接折算到单卡或生产服务。

未核实针对 v1 的公开同行评审或独立复现。文中用 Gemini‑2.5‑Pro 评分的部分属于作者的评测，不是外部评议；检索、数学与问答的数值也应按作者的实验设置解读。跨规模检查仍在 Qwen3-VL 这一家族内。
