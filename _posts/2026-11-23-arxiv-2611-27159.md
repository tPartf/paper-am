### 3. Introduction
交互 Agent 可以积累成功示范，但不一定每一条都值得用于有限的参数更新。作者固定执行器，单独量化经验选择给学生行为带来的变化。

### 4. Background
高 NLL 选择把难预测样本视为有价值；[LESS](https://proceedings.mlr.press/v235/xia24c.html) 则比较样本更新与目标梯度方向。是否允许跨任务选、是否强制保持类别覆盖，也会影响结果。

### 5. GPU 训练与数据报告
固定 Qwen3-4B-Instruct-2507，BF16、LoRA rank 16。两经验池、9 种选择条件、8 个初始化与 2 个抽样种子，共 288 个学生。每个全局规则挑 256 个独特内容、训练呈现 768 次，192 次更新。正文区分 224 学生的 62.146 GPU 小时与另 64 个基准的 17.419 小时；RTX 5090 型号见历史匹配实验附录。

### 6. 目标与方法直觉
用 40 条公开支持动作构建目标方向，把候选示范的 LoRA 梯度按冻结优化器统计量缩放后比较方向；挑高分内容，再从原始底座训练学生。评分预热权重不是学生初始化。

### 7. 贡献与创新
同为全局选择，开发面板中梯度法在两池成功率达 81.45% / 73.19%，比随机高 8.25 / 5.96 点，比高 NLL 高 4.10 / 4.05 点。另行冻结的 128 组保留任务上，按两源等权，优势为 +7.03 / +5.03 点。[表 2 与局限](https://arxiv.org/pdf/2611.27159v1#page=7)

### 8. 数据、工具与平台
训练示范来自 ALFWorld 文本交互的 API 与 Generic 固定池；开发与保留面板均使用同执行器。WebShop 仅做基座接口校准，不是第二环境的经验选择胜负。

### 9. 公开评价与独立评议
未核到公开评审。数据呈现次数对齐并不等于 token 或 FLOP 对齐，40 条支持动作也是先验成本。保留任务只检验同设置泛化；无连续多轮更新或旧能力保留结果。
