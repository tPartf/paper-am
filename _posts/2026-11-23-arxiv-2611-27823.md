### 3. Introduction

固定秩的 LoRA 更新便于部署，但要提升表达力，通常要扩大秩或添加独立分支。论文把容量问题改成每个 token 要在低秩空间里走多深。

### 4. Background

LoRA 先把输入投影到低秩空间，再映回输出维度。AdaLoRA 重新分配秩；HydraLoRA 使用共享下投影和多上投影；MoSLoRA 在低秩分量间混合。MoLR 比较的是复用同一个变换做多步更新的另一条路线。

### 5. GPU 训练与数据报告

PyTorch、NVIDIA A100。默认适配各线性层、秩 8、最大递归深度 2，每项实验 3 个种子。表 5 的 Llama-3.2-3B 测量：MoLR 对 LoRA 为 0.62 对 0.55 s/训练步、21.12 对 20.76 GB 峰值训练显存、0.69 对 0.18 ms/token。低参数增量不等于低推理代价。

### 6. 目标与方法直觉

先降维，再在小空间做共享的门控残差变换；阈值路由判断 token 是否继续，固定步位置信号区分递归阶段。训练时调整阈值以平衡深度使用。推理时可改最大深度，无须重新训练；这不是增加新的专家参数或常规权重合并。[§3、§4.4](https://arxiv.org/html/2611.27823v1#S3)

### 7. 贡献与创新

表 3 七项平均：Llama-3.2-3B 61.21 对 LoRA 59.21（12.17M 对 12.16M），Qwen3-8B 76.41 对 75.28（21.84M 对 21.82M）。平均领先不等于每项领先，例如 Llama 的 MMLU 为 55.48 对 LoRA 55.73。表 6 对照固定/随机深度，使路由的作用可检验，但没有解决端到端吞吐成本。

### 8. 数据、工具与平台

RoBERTa-B、DeBERTa-v3-L 用于 GLUE 七项，Llama-3.2-3B 与 Qwen3-8B 对比 ARC-Challenge、BoolQ、GSM8K、HellaSwag、HumanEval、MMLU、WinoGrande；另有图像分类组。HumanEval 报 Pass@1，其余推理组项目用准确率，因此七项平均是汇总分，不是一个统一数据集的准确率。

### 9. 公开评价与独立评议

未核实公开评审。独立判断：优势是把参数量和每 token 使用的计算深度分开；不足是部署时不能获得可合并 LoRA 的简单推理路径。更强的检验是对齐推理吞吐或延迟，再和高秩 LoRA 比较，同时检验路由在接续任务中的稳定性。本文未证明持续学习抗遗忘。
